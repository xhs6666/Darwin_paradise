## 阅读与维护

1. 先在首页阅读业务主流程，点击节点进入相关方法。
2. 按模块或脚本查找方法。菱形为判断，圆角为入口/出口；蓝色为普通步骤，紫色为挂起/异步，虚线为异常或动态边界。
3. 调用页显示编译时可确定的目标；事件注册、委托、接口/虚方法不是已证明的运行顺序。源码按钮显示完整原文与行号。
4. Editor/Player分别分析；同一方法可切换条件编译视图。Shader/HLSL单独标记，不与CPU方法混淆。
5. 更改源码后运行 `powershell -ExecutionPolicy Bypass -File Tools/FlowDocs/Generate.ps1`，再运行 `python Tools/FlowDocs/validate.py`。不要手工改生成数据或脚本分图。


## 分析边界

- 编译器控制流块反映局部分支/循环/返回；不测量运行时间，也不规定不同MonoBehaviour的全部先后顺序。
- catch入口用潜在异常边标注，finally与异步/协程恢复保留区域和语句，仍需结合源码看异常传播。
- 无方法体的接口/自动访问器标为声明；动态调用和外部引擎/系统API明确列出，不凭名称伪造实现。
- GPU函数通过兼容语法抽取控制结构；名称链接只表示候选，着色器宏/include的完整执行需结合渲染管线。
- 精确覆盖与源码SHA256见 [coverage.json](coverage.json)。语义分析诊断一并公开，不能把未解析调用当作没有调用。
