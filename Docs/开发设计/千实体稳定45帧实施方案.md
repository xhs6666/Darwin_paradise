# 千实体稳定 45 FPS 实施方案

2026-11-19 · 设计稿 · 实施起点为 `codex/thousand-entities-45fps` 的 `4e0c866`。

## 目标和已知差距

在现有 Windows 测试机、D3D12、2560×1385 和原画质下，让约 1,000 个**活跃实体**在 1 倍模拟速度时稳定运行。验收要求每个正式运行场景平均至少 45 FPS、P99 帧耗不超过 22.22 ms，并核对游戏时钟、物理交付及关键行为。普通实体在远景或视野外也继续参与生态。手控、战斗、跳跃、跌落、过河、溺水、繁殖和存档都应保持各自的正常规则。

| 现有证据 | 结果 | 实施含义 |
| --- | --- | --- |
| 最终 Windows 短测，活体 1,004→967 | 轨道 186.94 ms、P99 230.34 ms；近景 184.90 ms、P99 238.24 ms | 平均帧耗还需减少约 88%，优先改变计算的执行方式 |
| 最终暂停短测 | 轨道平均 15.97 ms、P99 35.24 ms；近景平均 15.27 ms、P99 21.26 ms | 暂停也有尾延迟，需要单独定位渲染、界面和后台争用 |
| 上一轮带计时长采样 | 重力 60–63 ms，包含岸线约 21 ms 和地面探针约 13 ms；中枢 44–47 ms，归入实体调度 | 先做物理与中枢。父子区间有重叠，最终构建需重测分项 |
| 存档与时钟 | 后台已负责写盘，主线程存档阶段最高 412–439 ms；游戏时钟约 1 倍速，物理使用 0.02 秒固定步且单帧补步上限 0.08 秒 | 分开测量存档阶段以及游戏、物理两种时间的实际交付 |

短测每组运行只有 65–66 帧。长采样包含插桩且来自较早实现，发布版 GPU 计数器也未取得有效结果。它们足以确定实施顺序，模块收益和瓶颈归属将在同版本复测确认。历史测量见 [Windows 实测与回归记录](../验证记录/性能验证汇编.md#thousand-entities-45fps-2026-11-18)。

## 整帧预算

| 模块 | 目标预算 | 主要计量边界 |
| --- | ---: | --- |
| 中枢、感知、任务 | 4.00 ms | 资格和事件、目标搜索、意图刷新、战斗候选 |
| 重力、岸线、碰撞 | 6.00 ms | 马达执行、批量解算、接地与水体查询、精确回退、物理引擎 |
| 生命、环境、种群 | 3.50 ms | 营养、修复、伤害、成长、资源和种群结算 |
| 渲染和界面 | 5.00 ms | 主线程提交、界面更新及阻塞；另记渲染线程与 GPU 时间 |
| 调度、存档及余量 | 3.72 ms | 调度自身、同步采集、集合变更、双物理步及偶发事件 |
| 合计 | 22.22 ms | 正式验收以墙钟整帧分布为准 |

分项用于设计和定位。记录排除子项后的主线程耗时、关键路径上的任务等待，以及各线程各自的耗时。预算内仍可能出现同帧峰值，P99 必须按实际整帧单独验收。

## 实施顺序

### 0. 固定测试入口与时序账本

- 将隔离的 Windows 压测入口整理成可复跑的开发工具，保存构建提交、存档和配置哈希、镜头路径、窗口尺寸、画质、图形 API、随机种子、活动实体数及后台进程情况。部署版在未启动采样时保持普通运行。
- 同帧记录墙钟间隔、游戏时间交付、实际物理步数及步长、各队列的延迟、活体与刚体数量、GC、主线程与 GPU 计数器状态，以及存档开始到完成的时间线。采集出生、死亡、命令、入离水与事件积压的计数。将插桩归因与无插桩 FPS 采样分别执行。
- 建立暂停、空世界、250、500、1,000 活体的曲线，区分固定成本、按实体线性增长的成本，以及密集群体引发的突增。对比 4e0c866，优先确认同帧的物理补步、地形查询、UI 或渲染等待。记录每步和每模拟秒的成本，方便比较处于不同帧率的版本。

### 1. 批量解算普通实体运动

- 从 `PlanetGroundPhysics`、`EntityGroundProbe` 和 `LandRoutePlan` 提取可批量执行的纯数据计算。每个物理步集中收集同一星球的变换、地形版本、实体位置、速度、身体范围与运动能力。先保留 PhysX 刚体，批量计算径向、地面高度与法线、移动许可及候选速度，统一提交实际变化。分别测量收集、计算、等待、刚体写入和 PhysX 的成本。只有测得纯计算值得并行时，再接入 Unity Jobs/Burst。
- 用真实三角网格和水文数据建立保守空间索引。可走陆地块需要有足够的水位余量、可接受坡度和有效支撑面。以预计位移、身体全宽、可能推离的余量和相邻实体的扫掠范围验证**整个运动走廊**；触及索引边缘、空间数据过期或结论不确定时复用现有精确判断。地形更换、星球变换、传送、体型或碰撞形状改变要即时作废相关结果。
- 若保留全部刚体后仍显著超出 6 ms，并且证据显示刚体交互是主要限制，再试验普通陆地实体的批量表面运动。岸边、水中、落地、跳跃、推挤、密集接触和手控由精确路径接管。进入边界前一物理步完成交接，同一物理步由单一解算器写入位姿。传递位置、速度、接地及水体状态，保存可逆的回退开关。碰撞规则允许跳过的对象与覆盖比例由成对实测决定。
- 用原路径和新路径从同一位置、速度和输入回放，对比斜坡、窄河、曲面接缝、碰撞后漂移与控制交接。按 1,000 实体样本记录快路径适用率、误判、回退原因和精确对象数量。若密集场景里回退足以耗尽预算，先缩小并定位交互成本，再决定是否扩展批量解算的范围。

### 2. 中枢按事件与游戏时间工作

- 将 `CentralGeneLogic` 拆为行动资格、意图决策和执行消费。基因重算只更新静态能力，角色、附着、手控、死亡、入离水和目标失效由现有状态源投递变更。采用实体身份与状态版本，避免旧任务结果覆盖新命令。逐个接通事件源，过渡期间对未接入的状态继续读取实时值。
- 在 `EntityWorkScheduler` 按游戏秒分批调度普通感知、巡逻、补给和规划，维持 0.25–0.5 游戏秒刷新窗口。实体间错开首次到期时刻，保留每个实体的到期时间；处理命令、受击与关键阈值的队列优先于普通查询。事件在下一次可执行的模拟边界生效，保存原有任务优先级和攻击冷却时间。
- 感知、队形和路线共享同一个版本的空间快照。普通候选搜索可批量进行；实际攻击、进食或搬运提交前，在权威模拟中核验生命、距离、目标与资源归属。移动马达按物理步持续消费最后一条有效意图。A* 先沿用全局预算，通过复测再决定是否调整。
- 验证命令覆盖与撤销、失活或死亡目标、饥饿转寻食、受击反应、手控交接、保存后任务恢复，以及暂停与恢复。正式结果同时报告决策次数、最大等待和超期情况。

### 3. 批量结算生命、环境与种群

- 以 `EntityWorkScheduler` 作为普通活跃实体的数据收集入口，先建立批量读取和提交。将饱食、储备、生命、环境与角色的索引用于热循环，与 `EntityVitals` 和 `EntityEnvironmentHazard` 的现有规则对照。按累计游戏时间结算可证明线性的区间。
- 饥饿、补仓、修复、持续伤害、入水、孵化、阶段切换和死亡按原有顺序跨阈值；临界状态继续精确结算。相互争用的资源、繁殖、出生和移除由权威线程按原顺序提交。沿用已优化的种群索引，采集种群成员变化和共享查询的次数。
- 用同种子、同事件输入回放对照营养、生命、年龄阶段、出生死亡与资源总量。对允许浮点漂移的字段，先测原实现跨重复运行的误差，再确定容差，记录第一个不符的实体与模拟步。

### 4. 压低自动存档和暂停尖峰

- 为 `WorldSessionManager` 分别计时实体与形态抓取、引用冻结、校验、序列化、写盘与清理。逐步维护可冻结的实体和规则数据，在明确的模拟边界记录同一世代的时钟、实体、地形、任务和资源。后台基于独占、不可变的普通数据做纯校验、序列化和写盘；Unity 对象访问继续由主线程处理。禁止将若干帧的可变状态拼成一个快照。
- 复用现有存档格式、原子替换和上一代备份。保持单写入顺序；慢盘时自动保存可合并待写请求，并报告待写年龄和失败状态。显式保存、退出、换世界要处理已开始的写入，并以实际落盘结果反馈。模拟磁盘满、文件锁、后台异常、连续自动加手动保存及中途退出，核对主档和备份的实际可读性与世代顺序。
- 对最终版轨道暂停的 35.24 ms P99 单独录制 CPU、渲染与 UI 时间线。先从远景批次、界面布局刷新、地形、云和海面的提交与等待定位。按证据采用空间分区、可见性或界面脏更新。保持指定画质下的近景形态、水面和选中反馈。比较同镜头暂停与运行的峰值，核对优化过后的暂停与继续操作。

### 5. 联调、回退和合并

按“测试入口 → 物理批量查询 → 中枢事件与调度 → 生命和种群 → 自动存档与渲染 → 整体验收”组织提交。存档和暂停归因从第 0 阶段开始，确认瓶颈后可独立实现。每阶段保留可切回的原执行路径，旧、新路径使用同一输入复放；功能回归失败、主线程等待抵消收益或代表场景明显退化时，恢复模块默认路径并保留测量证据。

普通、精确两条运动路径及两种存档执行方式共用同一套实体身份、世界状态和当前存档协议。验证本地权威和服务端入口，以及联机副本的权限边界，再决定新路径默认启用范围。最终合并以完整 Windows 验收和功能回归通过为条件。

## 验收矩阵

| 场景 | 主要检查 |
| --- | --- |
| 轨道与密集近景，分别暂停和运行 | 帧时间分布、视角切换、实体可见性、暂停后恢复 |
| 密集群体、战斗、围堵和推挤 | 反应时延、命令、冷却、伤害、碰撞及精确路径峰值 |
| 河流、湖岸、落地和玩家手控切换 | 全宽扫掠、碰撞交接、游泳与溺水、无穿地与异常推离 |
| 正常生态运行，期间多次自动保存 | 帧时间包含保存窗口，检查快照一致性、备份、重启读档及写入顺序 |
| 局部高压和长期运行 | 队列延迟、实体和资源变化、内存与积压趋势 |

- 同一设备串行测试，预热结束后每个正式运行场景至少采集 120 秒，重复 3 轮。自动存档用例至少包含 3 次自动保存事件，按实际间隔延长采样；另跑至少 30 分钟检查积压、内存与连续存档。正式场景保留真实出生、死亡和环境变化，预先安排可重复的约千活体夹具，并报告各窗口的活体数和活跃比例。数量明显跌出约千规模的窗口补跑。
- 各正式运行场景逐轮报告平均 FPS、P95、P99、最大帧耗、超过 22.22 ms 的帧数以及最长连续超时。自动保存和战斗峰值计入对应场景。以平均 FPS ≥45、P99 ≤22.22 ms 作为帧率合并门槛，同时检查暂停尾延迟。
- 提案验收误差为 120 秒窗口内游戏时钟和实际物理推进量各自距离 1 倍不超过 2%，并在短窗口检查是否持续掉步或积压。保留手控、损伤、任务和种群的行为回归。测试报告附实际设备、运行参数、原始采样、失败窗口与回退状态。

项目约定与模块预算见 [开发规范](../../agent.md#千实体实时性能验收)。
