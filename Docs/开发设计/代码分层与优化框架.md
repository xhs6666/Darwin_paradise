# 代码分层与优化框架

日期：2026-11-16。范围：`Assets/DarwinPark` 内的每个 C# 文件；编辑器回归代码单独统计。

## 目标与约束

以职责和依赖方向拆分，而不是单纯增加文件数。保留现有 MonoBehaviour、场景 GUID、公开接口和存档字段；不改动当前未提交的坐标、地理和文档整理工作。长文件不必然慢，小文件也可能包含全局扫描；结构治理与帧耗时必须分别验证。

## 分层后的框架

| 层 | 承担的职责 | 允许依赖 | 禁止事项 |
| --- | --- | --- | --- |
| 数据契约 | 版本清单、配置 DTO、存档/网络快照字段 | 基础数据类型；现有游戏 DTO 暂保留 Unity 向量 | 执行游戏逻辑、创建界面 |
| ServerCore | TCP 分帧、连接生命周期、版本与入服状态机 | .NET 标准库 | UnityEngine、UI、场景对象 |
| 权威模拟 | 生态、寻路、繁殖、伤害、实体调度、世界状态 | Core、Genetics、Entities、Planet、Environment | 读取本地输入、依赖显示帧或相机 |
| 服务端适配 | 玩家权限、命令执行、快照采集与广播、专服启动 | 权威模拟、ServerCore、共享 DTO | 客户端插值、面板构建、鼠标键盘输入 |
| 客户端适配 | 副本应用、插值、本地输入转换为命令 | ServerCore、共享 DTO、客户端展示 | 权威伤害/繁殖/存档、接受自报权限 |
| 表现层 | 界面构建、文本格式化、相机、特效 | 只读状态、命令提交接口 | 直接越过权威接口修改在线世界 |
| 编排入口 | 组装、生命周期、路由 | 服务接口 | 把业务分支、控件构建和持久化重新堆在入口 |
| Editor / Tools | 构建、静态检查、回归与维护文档 | 运行时接口 | 被运行时程序集引用 |

`DarwinPark.Gameplay` 统一拥有世界生命周期、存档校验/迁移、参数更新、权威批量落点、种源、模板与网络会话。`DarwinPark.UI` 提供界面、相机、输入与客户端副本适配，引用 Gameplay；`DarwinPark.Server.Unity` 同样引用 Gameplay，但不再引用 UI。Gameplay 通过可选表现适配器请求镜头/收藏/输入恢复，专服不安装适配器也能运行。旧 `DarwinPark.UI` 命名空间与组件 GUID 保留以兼容场景和调用，程序集边界由 asmdef 强制保证。`ServerCore.asmdef` 继续硬性禁止引擎引用。

## 优化顺序与拆分方式

1. 联机：会话入口只路由，服务端运行时与客户端运行时分别拥有各自状态；编辑意图与编辑执行器分开；TCP 和入服版本规则独立。
2. 实体信息面板：从视图中抽出只读信息格式化器；既有 partial 只保留必须共享序列化状态的视图布局，避免只用 partial 掩饰职责混杂。
3. 底部控制栏：将时间控制、图层选择、星球参数控件从入口拆为视图子模块；这一类纯视图拆分允许 partial 保留 Inspector/场景绑定，业务计算必须是独立类型。
4. 世界会话：将配置恢复、实体恢复、快照采集与磁盘写入分层；本轮先移除相机和渲染帧对专服的硬依赖，保持存档格式不变。
5. 高频模拟：先查工作调度器、气候和邻域查询的重复扫描、分配与失效边界。没有对照性能数据，不改变算法或宣称 FPS 提升。
6. 编辑器回归：长测试按场景分组，不按运行时代码的体量阈值机械拆分。

## 逐文件检查标准

使用 `Tools/audit_code_structure.py` 读取每个源码文件，生成逐文件结构清单和超长方法候选。它检查行数、方法体规模、生命周期、引擎依赖、网络角色混用与查找/分配调用。扫描结果是结构风险线索，不等于完成所有业务路径的语义证明。

人工重点检查跨职责入口及修改过的调用链；每轮更新清单，明确已完成项和后续项。方法超过 100 行、运行时文件超过 500 行列为优先检查候选，不作为自动拆分/自动判错条件。

## 验证与交付边界

- 结构：程序集无循环；ServerCore 无引擎引用；服务端适配器无 Camera/Input/屏幕等待；场景与 meta GUID 不变。
- 行为：未握手/未准备连接不能执行命令，协议/内容不兼容在世界下发前拒绝，客户端副本不写世界存档。
- 构建：分别检查编辑器、客户端、服务端编译条件；专服构建必须实际加载、监听、保存、重启才算完成运行验证。
- 持久化：原格式继续可读；未来格式拒绝；更新前独立备份；二进制与数据目录分开。
- 性能：结构拆分不承诺加速；需要用同世界/同规模/同镜头的原始测量另行评价。

## 2026-11-16 架构收尾与同类合并

- 从 UI 迁移 14 个脚本到 Gameplay 的 World、Spawning、Networking 目录；现有组件 `.meta`、类名、公开方法和存档字段保留。服务端与玩法层均禁止引用 UI 程序集，源码检查另外禁止相机、输入、界面和帧末渲染等待。
- 合并 11 个辅助脚本：世界存档收纳状态校验与旧生态计时迁移；网络协议收纳发行和配置；模板管理收纳磁盘存储；实体信息收纳三组状态文本；诊断界面收纳诊断报告格式化；感知收件箱收纳反向订阅；主行为选择收纳缓存。公开类型保留，旧 GeneAuthorityCache 入口在合并文件内转发。独立的狩猎候选筛选 PerceivedTargets 保留，因为它与观察分发存在不同算法依赖。
- 批量放置的地表查询迁到 WorldEntityActions；基因深复制由 Genome.Copy 统一负责，原 EntityPlacementUtility 接口继续转发；同步实体生成由 EntitySpawnCapture 统一取得新实体，移除加载/副本恢复中每次复制全体再查差集的路径。
- 参数更新不再读取 UIRoot 或等待 WaitForEndOfFrame；界面隐藏、光标和进度由可释放的客户端适配器接管。专服可直接执行同一更新服务。
- 专服没有收藏界面时，仍按稳定实体身份保留读入的 favorite 字段，避免分层后无表现适配器使存档信息丢失。
- 两个新的适配脚本抵消部分文件减少，C# 文件净由 433 降为 424。按职责合并，不把同一前缀但依赖不同的算法、MonoBehaviour 或大型视图强行拼成巨型文件。MonoBehaviour 保持独立文件和组件身份。

所有文件继续纳入结构和语义编译检查；这不代表每个玩法函数的全部分支均已运行，也不构成整场景 FPS 提升证明。真实世界与 UI 的回归、服务端包及最终证据记录于验证手册。
