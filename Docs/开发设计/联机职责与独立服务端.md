# 联机职责与独立服务端

更新：2026-11-17。

## 两文件开服入口

Unity 菜单 `DarwinPark / Build / Windows Server Core (Core + Start)` 从项目重建服务端并封装下载包。下载包只有 `DarwinCore.zip` 与 `Start.cmd`；前者包含实际游戏内容和运行依赖，后者调用系统 PowerShell 校验并自动释放 `.runtime/<核心哈希>`，首次创建 `data/server.json`。已有配置及世界数据保留，控制台通过 `stop` 保存停服。详情见 [核心构建与便携开服说明](../../Tools/DarwinCoreBuilder/README.md)。

`DarwinServer_Data`、`MonoBleedingEdge` 和 `D3D12` 收入核心内部，不能直接删除运行依赖。Burst 标注 `DoNotShip` 的调试目录从发布包排除。部署机器无需 Unity 编辑器，内部模拟仍使用随核心提供的 Unity Player。

## 当前架构

服务端通过本 Unity 项目构建为独立无界面的权威程序。构建机需要匹配的 Unity 编辑器、许可证和构建模块；部署机器直接解压完整核心包运行，无需安装 Unity 编辑器或 Unity Hub，也无需工程源码。完整包包含 DarwinServer.exe（Linux 为 DarwinServer）、随包的 Unity Player 运行库、程序集和资源目录，必须一起部署。

`ServerCore` 不引用 Unity，只承担网络分帧、版本校验和入服状态；生态、物理和地形模拟使用完整包附带的 Unity Player 运行库。这里的运行库依赖不表示开服需要启动或安装编辑器。单独一个脚本 DLL 或脱离资源目录的 EXE 均不构成完整游戏服务器。

| 模块 | 职责 | 依赖边界 |
| --- | --- | --- |
| `ServerCore` / `DarwinPark.ServerCore` | TCP、版本兼容、入服状态机 | .NET 标准库，禁止 Unity 引用 |
| `Gameplay` / `DarwinPark.Gameplay` | 世界/存档/参数更新、种源/模板、网络会话与共享协议 | 模拟模块、ServerCore；无 UI 程序集依赖 |
| `ServerUnity` / `DarwinPark.Server.Unity` | 权威指令、快照、专服生命周期和健康凭证 | Gameplay 与模拟模块；无 UI 程序集依赖 |
| `UI/Networking/Client` | 世界副本应用、显示插值、输入提交 | 共享协议及本地表现 |
| `Gameplay/Networking` | 服务端接口、注册工厂、程序集访问约定 | 不直接引用服务端实现 |
| `Gameplay/Networking/LanSession` | 会话入口、连接与生命周期编排 | 通过接口调用权威服务端 |
| `Tools/DarwinCoreBuilder` | 构建、校验、发布、更新及回滚 | 独立进程，不进入游戏运行时 |

普通客户端开房时同时运行本地权威服务端和界面；远程成员只运行副本。专服构建剔除场景菜单、HUD、相机、视频和音频监听等组件，运行时生成的实体仍有部分表现组件，尚未完成所有渲染数据的专服裁剪。

## 计算归属

| 计算 | 服务端权威计算 | 客户端计算 |
| --- | --- | --- |
| 入服与权限 | 版本握手、成员准入、加载确认、命令合法性、阵营权限 | 连接、展示状态、提交意图 |
| 时间 | 推进、暂停、流速及生产时间 | 应用远程时间、格式化日期 |
| 坐标与视野 | 位置登记、共享空间查询、地理信息、感知结果 | 为检查和显示建立必要的本地只读状态 |
| 寻路与移动 | 可达性、路径预算、AI 转向、物理位置 | 发送输入、位置方向插值 |
| RTS | 所属权、队列、目标合法性和命令执行 | 框选、指令标记、输入预览 |
| AI 与生态 | 目标、战斗、觅食、繁殖、突变、资源与种群 | 不独立推进同一权威生态 |
| 伤害与生存 | 温度、淹水、代谢、伤害、死亡、营养转移 | 血条、状态文本、表现 |
| 地形与气候 | 种子、参数及影响寻路和伤害的权威结果 | 首次载入时重建网格、纹理和必要的显示数据 |
| 基因与外观 | 决定实体属性、行为和遗传结果 | 根据同步信息计算外观、UI 和表现所需属性 |
| 编辑 | 再次检查权限和数值，执行合法修改 | 编辑草稿、提交请求 |
| 存档 | 采集、验证、原子写入、自动保存、备份 | 副本不写权威世界；本地偏好可保存 |
| 渲染与输入 | 不参与界面输入裁决 | 相机、鼠标键盘、UI、渲染、音效 |
| 构建和更新 | 独立更新器请求保存停服和部署新核心 | 客户端需自行升级到兼容协议和内容版本 |

客户端仍有地形和外观计算，其结果用于本地展示。伤害、繁殖、资源与世界存档以服务端结果为准。

## 构建和开服

优先使用 [DarwinCoreBuilder 操作说明](../../Tools/DarwinCoreBuilder/README.md)，提供图形界面和命令行。工程使用 Unity `6000.3.14f1`。游戏更新后重新运行构建，工具调用专服入口，收集完整运行文件并生成带清单的 ZIP。

Unity 菜单入口仍可直接使用：

- `DarwinPark/Build/Windows Dedicated Server`：需要 Windows Server 模块。
- `DarwinPark/Build/Linux Dedicated Server`：需要 Linux Server 模块。
- `DarwinPark/Build/Windows Headless Server (no server module)`：Windows Player 加专服编译标记，无界面运行。

完整解压核心包后双击 `Start.cmd` 可控制台开服，默认配置位于 `data/server.json`。首次从模板复制，之后保留修改；停服后修改端口、世界、种子、运行频率、自动保存等参数，重启生效。控制台实时显示日志，输入 `status` 查看状态，输入 `stop` 保存停服。数据独立部署可运行 `powershell -File ./Console.ps1 -DataDirectory D:/DarwinServerData`。已有世界的地形和气候按存档恢复，不因修改新建参数而重建。

已有完整构建可手工开服：

```powershell
./Server/Start.ps1 -Executable ./Builds/Server/Windows/DarwinServer.exe -DataDirectory 'D:/DarwinServerData'
./Server/Stop.ps1 -DataDirectory 'D:/DarwinServerData'
```

必须先等待保存成功并退出，再替换任何程序文件。首次从 `server.example.json` 初始化配置，此后不覆盖已有 `server.json`。默认端口 47777，可配置。`worldId` 为空时首次创建并写入 `server-world.json`，之后恢复该世界；读取失败会退出，不创建替代世界。

## 版本与更新

发行清单位于 `Assets/Resources/Entities/server_release.json`，构建时嵌入程序；旁边的 `release.json` 是运维副本，修改它不能改变二进制的兼容规则。

| 字段 | 含义与规则 |
| --- | --- |
| `release` | 完整核心和游戏的发行版本，供追踪、健康检查与发布 |
| `protocol` | 消息格式与语义，不同协议拒绝入服 |
| `contentEpoch` | 权威模拟和内容解释的破坏性变化，客户端和服务端必须一致 |
| `minimumSave` / `maximumSave` | 经过实现和验证的存档格式范围，不能只改数字伪装迁移 |
| 包 `schema` | 独立更新器的包清单格式，与游戏协议分别管理 |

客户端未加入、未完成本次世界加载确认或已被拒绝时不能执行命令。旧世界的确认消息不能放行新世界命令。

更新器执行预检、保存停服、完整离线备份、新目录安装、世界加载及监听健康检查，然后提交当前版本；失败自动恢复旧二进制和更新前数据。配置、存档、日志与发行目录分开。更新过程中用事务文件、进程启动凭证、数据租约和维护令牌避免误判与并发写入。

自动更新只允许相同内容纪元且新存档范围覆盖旧范围。尚无跨纪元迁移。Linux 包可以构建校验，目前由运维手工部署；断电后未完成的事务需要按工具文档人工核实和恢复。

## 验证边界

本轮客户端、服务端、编辑器三种条件下的托管源码编译均通过，零警告和零错误。23 项网络回归、6 组气候基准、16 项核心包与模拟子进程更新回归通过。程序集、GUID、流程图与文档索引另外执行结构校验。

2026-11-16 后续已在获准的普通执行环境通过 Curl 缓存检查，使用隔离项目副本完成真实 Windows 无界面服务端构建。构建另修复了场景裁剪失效引用、错误场景缓存复用、Burst 临时目录访问和新世界初存把加载暂停误存为永久暂停的问题。最终产物及实际验证见[构建与工具汇编](../验证记录/构建与工具汇编.md)的后续记录。协议探针不是实际游戏客户端；真实客户端联调、长期稳定性、真实升级回滚和完整表现组件裁剪仍未验收。


2026-11-16 架构收尾后：Gameplay 接管完整世界/存档/参数编辑/生成与网络会话，ServerUnity 无 UI 程序集引用。新完整核心包及 51 项世界/18 项真实服务端检查见[构建与工具汇编](../验证记录/构建与工具汇编.md)。
