## 合并计算性能修复验证-2026-11-08

### 合并计算性能修复验证（2026-11-08）

<a id="doc-23909002fd4c-问题与定位"></a>

#### 问题与定位

用户反馈本地有输入延迟，合并计算后更卡，截图显示约14 FPS / 72.4 ms。检查发现原调度每帧对活跃实体排序，比较器反复GetComponent与读取数值；静止实体到期时重新拼接长基因/数值键、创建组和桶列表、遍历已加入成员反复写组大小；每个0.1秒小步又对所有成员重复查询组件并构造LINQ闭包。孤立实体没有共享成员，也承受完整的代表验证和取样流程。

旧版原生基线确实存在退化：400个分散生产者、每次交付0.25秒时，完整合并结算平均43.4323 ms，逐体结算27.7164 ms。该基线从已提交版本0fb3c6a提取调度/共享核源码，在独立测试工程运行；主工作区和原存档保持完整。

<a id="doc-23909002fd4c-修复范围"></a>

#### 修复范围

- 三档任务优先级改用线性分桶，控制中、受伤、普通实体依次执行，保留执行前死亡检查。
- 兼容组用值类型键和预计算散列，完整基因签名只在逻辑版本变化时生成；比较仍包含年龄、孕育、状态、启停、营养分段、容量、健康及体型，不以散列相同直接判为兼容。
- 分组对象和成员缓冲复用，空间桶以链表串联组；组大小在分组完成后统一写入。
- 组件上下文按帧刷新，小步直接检查实际字段；主繁殖逻辑只在基因逻辑版本变化后重新获取。受伤、环境压力、阶段、变异等继续拆组。
- 单成员组沿原逐体生命与营养入口补清累计时间。多成员组继续共享代表变化，不共享实体身份和独立孕育。
- 清除无实体引用的旧基因签名，避免长期变异留下无限增长的缓存。

<a id="doc-23909002fd4c-测量方法与边界"></a>

#### 测量方法与边界

`SchedulerPerformanceRegression.RunBatch`在原生Unity编辑器中运行。400个实体分别采用密集、分散、70%生产者加30%移动基因三种分布，先预热60次，再计时180次；比较1/60秒及0.25秒两种交付步长。两条路径均纳入正常/共享的基因、寿命及代谢结算，不能将只计基因的旧探索测量当成公平对照。微测量关闭环境及物理移动，保持相同出生模板、数值与随机种子。

另从原存档副本加载208个实体，分别开关合并，预热1秒、测量4秒，包含正常UI、环境与物理。副本降低地形分辨率以隔离调度开销，后台自动补充关闭，保留正常繁殖；不写用户原存档。该结果不等于用户完整地形或发布版的最终FPS，短时峰值也受编辑器及其他进程影响。

Unity Mono在本机的GetAllocatedBytesForCurrentThread恒为0，因此不使用这个数宣称零GC。本次记录热循环新增分组对象数，另以生命周期回归验证缓冲复用和签名回收。

#### 原因与修复

种群成员读取移动或攻击属性时，会反复筛选种群基因、排序全局成员查找王后，并扫描全部蚁群判断是否被搬运。状态机、运输、生命属性和 UI 又重复调用这些查询，使工作量随成员和种群数量放大。

本次采用以下调整：

- 种群表达按评估对象缓存，群体成员、王后和领袖通过 `PopulationGroupIndex` 查询。成员加入、停用、死亡、角色变化及同帧表达变化都会使缓存失效。
- 运输实体、活体占用和尸体资源通过持久 ID 或对象索引查询；释放、模式变化、途中销毁和读档恢复同步处理索引。
