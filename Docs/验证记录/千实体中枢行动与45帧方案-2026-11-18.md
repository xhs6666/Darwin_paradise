# 千实体中枢行动复测与 45 FPS 方案

## 复测方法与结果

使用同一份从 1014 个活体开始的存档，每组重载，最后约 977 个活体。Unity 编辑器、D3D12、2560×1385、1 倍速。关闭自动投放和全局变异，保留移动、死亡、资源任务与物理。近景镜头覆盖约 44 个合并模型。每组采样约 8 秒。每个运行组每现实秒推进约 1 游戏秒，末尾无模拟时间积压。本轮仅在隔离项目加诊断标记。

| 运行条件 | 平均 ms/帧 | P95 ms | 帧数 |
| --- | ---: | ---: | ---: |
| 轨道暂停 | 41.71 | 59.19 | 192 |
| 近景暂停 | 35.32 | 40.98 | 227 |
| 轨道运行 | 340.32 | 434.22 | 24 |
| 近景运行 | 303.45 | 333.10 | 27 |
| 轨道运行复测 | 341.61 | 371.10 | 24 |

本轮编辑器环境比之前同档约 146 ms/帧的记录慢，分析使用本轮内部的范围、比例和调用数。毫秒数不能直接与之前相减来估算插桩开销。由于样本短，以上数据适合定位热点；发布版长测才用于验收。

关闭插桩、只记录墙钟帧时间后，轨道暂停平均 37.35 ms、P95 50.56 ms，轨道运行平均 297.35 ms、P95 333.93 ms，27 个运行帧中活体由 1009 变为 977，每现实秒推进 1.009 游戏秒。两轮由不同编辑器进程采集，不能用差值单独估算插桩开销。无插桩复测仍然明显慢于先前约 146 ms 的样本，本轮差异的具体环境原因尚未隔离。无插桩结果位于 Artifacts/GeneRiverReview/Project/Artifacts/Central45Raw。

## 中枢在算什么

同一实体在一个慢帧会跑多个至多 0.1 游戏秒的模拟小步。上一次千实体样本每帧约 1957 次中枢调用，本轮慢帧每帧约 3516–3920 次。马达已合批到每帧约 953 次执行，但中枢入口和节奏检查仍走各个小步。

| 分项 | 本轮平均 ms/帧范围 | 平均次数/帧 | 实际计算 |
| --- | ---: | ---: | --- |
| 行动入口 | 40.57–48.89 | 3516–3920 | 主中枢资格、附着和孵化限制、生命状态、行动马达、速度 |
| 决策节奏与签名 | 12.02–13.51 | 3423–3814 | 读取受击、命令和任务，比较状态，部分轮次重新算补给与饥饿签名 |
| 真正刷新任务意图 | 16.21–17.95 | 661–662 | 按优先级选蚁群分工、补给、命令、领地等目的地 |
| 马达执行，含路点与避让 | 11.60–13.23 | 953 左右 | 跟随现有路径、绕开近邻、转向、写速度 |

中枢全分支包括子调用，约 83–97 ms/帧；表中分项的包含耗时不能与全分支相加。入口中速度查询会进入生态属性修饰，检查蚁群角色、群体光环、附着、水中能力及速度上限，批内组件缓存仍有字典访问和动态状态检查。在本次以蚁群活动为主的存档里，约 17%–19% 的节奏检查实际刷新决策，捕猎和咬合入口几乎没有命中。战斗密集场景要另测。

## 实施路线与帧预算

先在同一台设备建立 Windows 独立运行版基线。发布设置、分辨率、画质、镜头路线和存档固定，墙钟帧时间使用低开销采集，脚本细项另开诊断轮。先做远景、密集近景、近岸水域、自动保存重载和混战记录，避免只测空载编辑器或某一种场景。

| 子系统 | 主线程预算目标 ms/帧 | 实施方法 |
| --- | ---: | --- |
| 中枢、感知和任务 | 4.0 | 基因表达、群组、装备或角色、受击、命令、补给阈值和入水作为更新事件。一次读取形成有效速度、主体资格和任务版本，供整个模拟阶段复用。普通个体每 0.25–0.5 游戏秒错峰刷新，重要事件立刻唤醒。马达消费最近有效意图，追击用已经采样的位置与已验证航段 |
| 地面运动、岸线和碰撞 | 6.0 | 为地形三角网和水位建立带余量的安全陆地区，只有扫掠范围完整落入同一已证明安全的区域才走快路径。逐步以批量位置、速度及邻域数组推进普通成员；玩家、冲撞、近岸、跌落继续走高精度刚体及真实水位。批量运动按实际交互风险升降级，状态和速度成对交接 |
| 生命、环境、基因、种群结算 | 3.5 | 稳定状态的代谢和温湿度用错峰批量结算，根据实际累计游戏时间推进。伤害、饥饿阈值、溺水和状态迁移即时处理。以整数属性槽和连续数组减少字符串字典及 MonoBehaviour 回调；纯数据阶段适合用 Jobs/Burst，伤害和出生由主线程按稳定顺序提交 |
| 渲染提交与界面 | 5.0 | 单独压低暂停开销。先在发布版定位地形、云、海面、尸体和实例提交的通道成本，再按屏幕占比做地形分级与分区剔除。避免全视图扫实例和停机世界的空回调。GPU 另设 P99 不超过 18 ms |
| 调度、存档和其他杂项 | 1.5 | 增量补充登记、资源和种群索引；主线程获取同一模拟时刻的稳定存档快照，后台执行 JSON 序列化、分区写入和原子更新清单，归还到主线程的结果有明确时间预算 |
| 帧波动余量 | 2.22 | 留给两次固定步、控制输入、特效及偶发变化 |

各子项是设计预算，需用性能样本锁定。50 Hz 固定步在 45 FPS 下也有同帧执行两步的情况，主线程验收要覆盖双物理步及一帧多个事件。修改频率时按实际模拟时间结算，不能用降低全局速度来刷帧。

### 验收

同一设备和画质下，使用约千个活跃实体、1 倍模拟速度。先保持规模做固定用例，每种关键镜头至少测三分钟；再做至少十分钟自然运行，包含一到多次自动保存、繁殖、交战和近岸进入/退出。提交平均帧率、P95、P99、50 ms 以上帧数、每现实秒实际推进的游戏时间、模拟积压以及活跃实体数。达标目标为平均至少 45 FPS 且 P99 ≤22.22 ms，自动保存不得产生 50 ms 以上尖峰，并对照检查行为和生态结果。交互极端密集、所有实体同时发生刚体碰撞的压力例单列结果。
