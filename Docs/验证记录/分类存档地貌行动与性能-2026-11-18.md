# 分类存档、行动与千实体性能复测

## 复测条件

每次加载同一个 1014 活体存档副本，采样结束时约 977 个活体。Unity 6000.3.14f1 编辑器、D3D12、2560×1385、1 倍模拟速度、固定现场镜头。关闭自然投放和全局变异，保留正常行动、死亡与物理。每组约八秒，实际推进约每现实秒一个游戏秒，采样末无模拟时间积压。旧版地貌保持原版本，避免地形变化干扰性能对照。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 整帧平均 ms | 147.83 | 145.90 |
| 整帧 P95 ms | 158.86 | 171.11 |
| 普通脚本回调 ms/帧 | 80.07 | 77.78 |
| 固定物理步脚本 ms/帧 | 44.88 | 44.64 |
| Unity 物理解算 ms/帧 | 4.43 | 4.31 |
| GPU ms/帧 | 11.04 | 10.45 |

两轮样本分别为 各 55 帧，整帧均值相当于约 6.8 和 6.9 FPS。P95 有波动，持续低帧率仍然存在。

全局 A* 队列约 0.11 ms/帧，部件远景提交约 1.5 ms/帧。岸线检查、地面探针和补给判断已减少重复调用。接下来若要大幅提高这类高活跃场景的帧率，需要进一步拆解中枢的每小步判断，以及减少普通实体每帧触发的固定物理步脚本数量。改动须分别检验持续位移、入水、碰撞与模拟推进速度。

## 存档与地貌

正常世界的 world.json 记录世界元数据和当前分区代号。地形与矿量、规则基因、实体数据、生态状态、部件构成各自独立。相同构成共享一条记录，恢复时按当前形体规则和表达输入核对。一次保存完整写出新分区，再原子更换清单，并保留上一版清单及其分区。旧单文件由现有读档入口读取，正常重新保存时写入分类格式。独立导出的备份文件仍使用可单文件搬运的完整快照。

第 6 版地貌使用带独立峰顶和山隘的短山脊，每组由一至三条相邻山脊组成。旧版地形仍按原版本生成，现有世界可通过带备份的地貌升级入口选择新版。湖床深度在地形生成阶段写入网格，默认地形显示根据真实湖底深度混合浅岸沉积物和深湖底色。

原始性能数据位于 Artifacts/GeneRiverReview/Project/Artifacts/WorldSystemBaseline 和 WorldSystemRelease。所有运行验证使用隔离项目和存档副本。


## 运行验证

- 完整存档实测保存约 267 ms，清单 1533 字节。977 个实体共用 47 份部件构成，重载后 977 个实体都直接使用磁盘恢复的构成。连续覆盖三次验证了上一代备份和已发布分区清理。测试使用暂停后的同步保存，运行期间仍可能出现单次存档峰值。
- 用数值表达为游泳状态、基因组不带独立游泳基因的实体，从干地控制进入真实河段。浸入后继续有切向位移。陆行对照在水下不给切向推进，碰撞与重力引起的跌落仍按原模拟结算。
- 普通种群成员到达自动集结点会释放行动权，避免个人巡逻休息又让种群停住。实测成员恢复自主位移约 1.44 个世界单位，显式种群命令仍可执行。
- 第 6 版种子 77441 的山脉采样可重复，湖床深度遮罩与陆地分离，实际网格有 212 个湖床着色顶点。
- 云层位置根据模拟时间计算。暂停并移动镜头后，云层角度、太阳相位和世界坐标保持一致。底栏可用波浪键显示及隐藏，输入框聚焦时保留文字输入。取消图层的默认键改为退格键。
