# 局域网、权限、RTS 与紧凑布局验证

## 实现

随机生成栏宽 480→240；主菜单宽 420→320，按钮高 48→58。截图检查缩短后的数量输入、来源、范围、生成/取消按钮无重叠。

同一程序内建 TCP 房主和客户端。Esc 可开放房间、选择作弊开关；主菜单多人入口可加入。房主唯一管理员，普通成员选择实体游玩，基因输入只读且屏蔽放置、随机生成等创造操作；服务端独立校验，不能靠伪造实体 ID 或管理员标志绕过。

R 切换 RTS，框选和右键指令接入真实行动、战斗及工匠运输。命令按基因、角色及实体占用过滤；普通成员王后只可指挥自己的种群。RTS 指令随房主世界成对保存和恢复。

## 真实双进程联机

运行 `LanMultiplayerRegression.RunHost` 与 `RunClient`，通过实际 TCP、完整世界加载和真实物理推进验收，房主 **17 项**、客户端 **25 项**全部通过：

- 唯一管理员、普通成员只读输入和所有创造入口拒绝；服务端拒绝伪造基因、放置、作弊及外群 RTS 请求。
- 普通成员不能暂停整个对局，不能中途换取另一实体；实体占用来自连接身份。
- 实际框选只包含本群，王后指令经房主推动士兵移动并同步到客户端；客户端自身不运行第二份物理模拟。
- 工匠采集使用原运输任务，攻击目标死亡会取消指令，离线管理员 RTS 实际移动及守卫指令写盘重读。
- 作弊开关不增加管理员；成员修改值、添加基因、放置和随机生成由服务端执行，关闭后立即失去编辑权限。
- 房主 Esc 菜单不暂停世界，远端随机生成仍完成；作弊成员启停请求由服务端同步。
- 普通成员 Q 能力按实际营养扣账，能量守恒；客户端保存入口不写房主世界。
- 立即取消连接后重新加入；离开释放占用；重连、房主关闭、重新开放、加载中途断线均正确清场。
