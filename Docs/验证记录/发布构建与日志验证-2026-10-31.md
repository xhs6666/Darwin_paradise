# Windows 发布构建与日志验证

## 构建失败原因及修复

`GUIStyleState.scaledBackgrounds` 只有编辑器 API。之前的 `dotnet build` 使用 `UNITY_EDITOR` 定义，无法发现发布版缺少该属性，因此编辑器编译通过仍会在 Build Player 时报 CS1061。

`RuntimeMenuTheme` 通过独立辅助方法，仅在 `UNITY_EDITOR` 内清除高 DPI 背景；发布版保留普通背景赋值。编辑器外观修复仍然有效。本次加入真正的非开发版 Windows 构建回归，不再用编辑器程序集编译代替发布验证。

首次实际启动还发现太阳和星空的 `Shader.Find` 字符串引用被裁剪，导致 `Material(null)` 异常。新增 Resources 材质显式引用 URP Unlit、Particles/Unlit 和启用发光的 Lit，保留太阳、星点、种群标记和能量块所需着色器及变体。最终发布程序中两个启动异常均消失。

同时把地表兜底温度计算中 `pow(1-latitude,1.2)` 的底数限制在 0～1，防止归一化浮点误差导致负底数，并消除对应 Shader 编译告警。

## 日志

场景 Awake 前启用，捕获 `Application.logMessageReceivedThreaded`。有界后台队列写 UTF-8 无 BOM 文件；默认 0.5 秒刷新、错误立即刷新、正常退出排空。4 MiB 分段、保留最近 20 个本功能日志，长消息截断、拥塞计数，其他实例正在使用的文件保留。

游戏目录不可写时回退当前用户数据目录。配置、启动环境、世界加载及保存、联机权限和断线、成批生成关键节点均可追踪。设置提供实际目录及打开入口，不增加游戏内遮挡面板。

## 执行结果

`PlayerBuildLogRegression.RunBatch` 在隔离工程中 **17 项通过**：

- JSON 配置、真实 Unity 普通/警告/错误/异常输出及堆栈、32 条工作线程输出、时间/线程/级别、中文 UTF-8 无 BOM。
- 重复初始化不重复订阅、不同会话独立文件、退出排空、注销后不继续写、关闭后文件锁释放。
- 首选目录不可用时回退、轮转后继续写、大小和数量限制、长消息截断、尾部保留和最新日志指针、禁用不建文件。
- 三个运行时材质依赖完整、发布场景存在、真实 Windows Standalone x64 非开发版构建成功。

最终解决方案编译 0 错误、0 警告。实际 Player 构建结果 `Succeeded`、0 错误，有 **1 条 Unity Cloud 提示**：未登录，无法上传原生调试符号；不影响本地发布和运行。告警原文保存在 `build-messages.txt`，未把它描述成整个构建 0 告警。

实际启动最终 `WindowsPlayer`，使用 Direct3D12，场景与底栏构建完成；自动生成包含中文系统信息的独立日志，日志中无 Error 或 Exception。烟测使用隐藏测试进程，之后只结束该测试进程，没有关闭主 Unity 编辑器；正常退出排空由日志回归实际读盘和释放文件锁验证。
