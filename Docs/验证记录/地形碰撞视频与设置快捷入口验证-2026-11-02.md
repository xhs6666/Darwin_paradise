# 地形碰撞、菜单视频与设置快捷入口

验证完成日期：2026-11-02（亚洲/上海）。Unity 6000.3.14f1，Windows 11。

## 修改

`PlanetTerrainMeshBuilder.ApplyGeneratedData` 在修改网格前先清空旧 `MeshCollider.sharedMesh`，根据实际三角形数选择烘焙选项。超过2,097,152三角形时关闭 `UseFastMidphase`，保留其他清理/焊接选项，不简化地形。切回普通网格时按Inspector偏好恢复快速结构，也允许手动关闭。

原菜单MP4为H.264 High Profile，包含B帧。保留原12秒游戏星球动画，转换为1280×720、24fps、YUV420P的VP8/WebM，使用Unity软件解码，避免原Windows Media Foundation的Flush/Unreadable Track路径。场景、默认路径和重新录制器同步更新，删除旧MP4及其meta；封面JPG保留。播放/暂停按意图变化执行一次，停用和销毁时停止解码并成对解除输出、释放RT。

底栏左侧的两个翻页按钮旁新增带齿轮的“设置”，两页共用。进入原有全局设置页；返回按钮和Esc使用相同恢复入口，恢复打开前的运行/暂停状态、HUD和输入。普通联机成员可操作本地设置，不获得世界修改权限。其他覆盖界面或加载期间拒绝叠加打开。

## 实际验证

在 `Artifacts/NutritionEcologyProject` 独立工程副本运行，没有打开或替换用户世界。

| 检查 | 结果 |
| --- | --- |
| `dotnet build Darwin_paradise.slnx --no-restore -v minimal` | 0错误、0警告 |
| `TerrainVideoSettingsRegression.RunBatch` | PASS，35项 |
| `PlayerBuildLogRegression.RunBatch` | PASS，17项；实际Windows非开发版构建，0错误 |
| Windows图形程序视频验收 | PASS：首帧、两次完整循环、暂停恢复、销毁解码器及正常退出；无WindowsVideoMedia或游戏脚本异常 |
| 资源检查 | 449个meta GUID有效且唯一；64个待提交C#脚本meta齐全、UTF-8无BOM |

碰撞测试真实生成2,116,800三角形的球面网格，经过正式 `ApplyGeneratedData` 上传、烘焙。验证自动禁用Fast Midphase，保留全部三角形，六个轴向及两个斜向射线均命中真实地面；重建回普通网格和手动禁用偏好均有效。

视频测试在Windows编辑器和实际Windows Player中完成。编辑器还覆盖三次停用/重新启用、进入世界暂停、返回主菜单继续、销毁时释放。首次退出测试尝试直接删除被菜单声明依赖的背景组件，被Unity依赖规则阻止；修正夹具为先销毁菜单组件，再销毁背景后，35项全部完成。

设置测试从真实生成世界的两页分别点击实际Button，检查输入门控、暂停、HUD隐藏和恢复、原已暂停状态及普通成员；0.7、1、1.4三档Canvas缩放下与左侧分页不重叠。实际截图位于 `Artifacts/TerrainVideoSettingsReview/shortcut-left-tabs.png` 及 `settings-from-page1.png`、`settings-from-page2.png`。

Player视频测试脚本仅写入隔离工程，以 `--menu-video-probe` 启动验收并主动 `Application.Quit`；主工程不包含此注入脚本。结果位于 `Artifacts/TerrainVideoSettingsReview/player-video-result.txt`，原生日志证明正常退出。构建报告有一条Unity Cloud未上传原生符号的提示，不影响本地构建；退出末尾另有D3D12 PSO缓存写入提示，不作为本次两个报错的修复项。
