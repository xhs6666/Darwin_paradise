## 发布构建与日志验证-2026-10-31

### Windows 发布构建与日志验证

<a id="doc-83f62d8cf3f4-构建失败原因及修复"></a>

#### 构建失败原因及修复

`GUIStyleState.scaledBackgrounds` 只有编辑器 API。之前的 `dotnet build` 使用 `UNITY_EDITOR` 定义，无法发现发布版缺少该属性，因此编辑器编译通过仍会在 Build Player 时报 CS1061。

`RuntimeMenuTheme` 通过独立辅助方法，仅在 `UNITY_EDITOR` 内清除高 DPI 背景；发布版保留普通背景赋值。编辑器外观修复仍然有效。本次加入真正的非开发版 Windows 构建回归，不再用编辑器程序集编译代替发布验证。

首次实际启动还发现太阳和星空的 `Shader.Find` 字符串引用被裁剪，导致 `Material(null)` 异常。新增 Resources 材质显式引用 URP Unlit、Particles/Unlit 和启用发光的 Lit，保留太阳、星点、种群标记和能量块所需着色器及变体。最终发布程序中两个启动异常均消失。

同时把地表兜底温度计算中 `pow(1-latitude,1.2)` 的底数限制在 0～1，防止归一化浮点误差导致负底数，并消除对应 Shader 编译告警。

游戏目录不可写时回退当前用户数据目录。配置、启动环境、世界加载及保存、联机权限和断线、成批生成关键节点均可追踪。设置提供实际目录及打开入口，不增加游戏内遮挡面板。

<a id="doc-22043057cf41-局部性能对照"></a>

#### 局部性能对照

Unity 6000.3.14f1，独立工程播放模式，同一进程分别执行旧实现与新实现，预热后计时5次取中位数。分配单独采样主线程GC.Alloc事件次数，每组64次调用；它不是分配字节数。

|路径|计时调用数|旧实现|优化后|64次调用的旧/新分配事件数|
|---|---:|---:|---:|---:|
|按实例ID查询基因表达|100000|9.144 ms|0.293 ms|128 / 0|
|随机命名|1000|6.078 ms|0.113 ms|1728 / 64|
|必有/必无基因条件匹配|100000|62.056 ms|3.611 ms|704 / 0|

随机命名仍会分配最终名称字符串；避免的是重复加载/解析词库。查询与条件匹配在该样本中没有托管分配事件。稳定的1000个模拟子步只构建1次行为快照，仍执行1000次Tick；重算发生在回调中时，下一个子步再使用新快照。

最初尝试的`GC.GetAllocatedBytesForCurrentThread`在本机Unity Mono返回0，因此未将其作为证据。最终使用Unity官方[主线程GC.Alloc记录方式](https://docs.unity3d.com/cn/6000.0/ScriptReference/Unity.Profiling.ProfilerRecorderOptions.CollectOnlyOnCurrentThread.html)，通过旧实现的非零计数和记录器容量检查确认采样有效。
