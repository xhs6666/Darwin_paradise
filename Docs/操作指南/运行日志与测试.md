# 运行日志与测试

游戏启动后自动保存日志，不需要打开开发者模式或手动开启控制台。编辑器播放与 Windows 发布版都生效。

## 找到日志

- 默认位置：游戏可执行文件旁的 `logs` 文件夹；编辑器播放时为工程根目录的 `logs`。
- 游戏中进入“设置”，点击“打开日志文件夹”可直接定位实际位置。
- 如果游戏目录不可写，自动改存到 Unity 的当前用户数据目录下的 `logs`，实际路径在设置中显示。
- 每次启动建立独立 `session-日期-时间-进程号-随机标识-分段号.log`；多人测试的房主和成员各自保存日志。
- `latest-log.txt` 记录最近创建的日志文件完整路径。同一目录同时运行多个实例时，可以按文件名里的进程号区分。

测试出现问题后，正常退出游戏，把对应时间的 `.log` 文件发来。若发生文件轮转，同一次启动的相邻分段也一起保留；联机问题最好同时提供房主与成员日志，并说明操作步骤和大致发生时间。

## 记录内容

每条消息带有时间及时区、级别和线程编号。普通输出、警告、错误及异常均保存，警告和异常保留堆栈；后台线程的 Unity 输出也会收集。日志还包括：

- 游戏/Unity 版本、系统和显卡信息、存档及自定义基因目录。
- 世界加载开始/完成、种子和实体数量、保存成功及实际文件路径，加载与保存失败原因。
- 联机开放、加入、实体分配、作弊开关、越权指令拒绝、离开和断线。
- 随机生成任务开始、完成和取消。

不会每帧记录玩家输入、位置快照或每个实体的所有基因，避免影响运行速度。日志并非完整的游戏录像。

## 文件限制

默认单文件约 4 MiB，超过后另建分段，目录保留最近 20 个本功能产生的日志文件。单条过长消息会截断；极端情况下队列满时省略消息并写入数量提示。其他文件不会被清理，其他实例仍打开的日志也不会被强行删除。

后台线程默认每 0.5 秒刷新，错误立即刷新，正常退出时排空队列。系统崩溃或强制结束进程时，最后尚未刷新的少量输出可能无法保存。Unity 自带的 `Player.log` 仍保留，用于补查引擎启动阶段或日志系统自身的故障。

这些容量和频率在 `Assets/Resources/runtime_logging.json` 配置；修改后重新构建生效。`enabled` 可关闭文件日志，不影响原有 Unity 输出。
