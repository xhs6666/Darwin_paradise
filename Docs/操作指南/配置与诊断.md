## 大气层颜色配置

编辑游戏目录下的 `config/atmosphere.json`，`dayColor` 为白天天空、`twilightColor` 为晨昏地平线、`nightColor` 为夜空。颜色使用 `#RRGGBB`，例如蓝色 `#3385FF`、橙色 `#FF4D17`。保留 `version: 1`；文件允许 `//` 注释。

保存后约两秒自动应用到当前大气层，不需要重启或重新生成世界，暂停时也可生效。无效颜色或 JSON 会告警并保留上一份有效配置；第一次启动缺少文件时从内置默认值生成。这是所有存档共用的显示配置，不修改存档中的地形和实体。

观察模式也显示昼夜：`enableDayNight` 控制普通地表、海水、河湖和云层的昼夜亮度，默认开启；`nightSurfaceBrightness` 为夜间亮度系数（0～1，默认0.15），`terminatorWidth` 为地表晨昏过渡半宽（0.01～0.5，默认0.12）。这些参数与颜色同样热更新。高度、气候和矿石等数据图层保留原有读图亮度，天空仍按真实太阳方向变化。

## 规则控制与观察基因

原文档：`Docs/操作指南/规则控制与观察基因.md`

<a id="doc-4ecb017bf956-规则控制与观察基因"></a>

### 规则控制与观察基因

<a id="doc-4ecb017bf956-第一页规则卡"></a>

#### 第一页规则卡

底部控制栏第一页新增“规则控制”，与地图统计/筛选卡均为260×164。宽屏放在筛选右边；窄屏通过右上方“规则”展开同尺寸浮卡，位于筛选浮卡上方。第二页继续保留种群档案。

右上列表选择“变异规则”“定时清尸”或“种群比例调节”。在“变异规则”页可切换“定时抽样／生命阶段”，并修改变异总开关、抽样比例或阶段概率及周期，点“应用并保存”后写入外部`config/gameplay.json`；已有中文注释、其他数值与未知字段保留，旧文件缺少新键时自动补齐。修改前读最新文件，以免覆盖在外部编辑的其他值，原文件保留`.bak`备份。`重载`重新读取外部文件。只读成员和联机副本不能绕过按钮直接执行保存。

默认10%、3游戏天一轮（内部30模拟秒）；暂停和全局开关关闭时不推进，倍率会影响轮次对应的实际秒数。比例0到100%，界面周期按游戏天输入：默认换算下为0.1到8640游戏天（内部1到86400模拟秒）。比例和周期变化用于下一轮，已抽出的剩余名单继续按原名额处理；缩短周期时会保留已累计时间。卡片显示轮次、上轮实际抽取/总活体数以及剩余待执行人数。

<a id="doc-4ecb017bf956-时间单位与比例调节"></a>

#### 时间单位与比例调节

默认1游戏天＝10模拟秒，365游戏天＝1游戏年。1倍速、负载正常时，1模拟秒约等于1现实秒，因此3游戏天约30现实秒；2倍速约15现实秒。暂停不推进，机器过载时实际所需时间更长。悬浮周期单位可查看当前换算；外部配置的 `mutationRoundSeconds`、`corpseCleanupSeconds` 继续以模拟秒保存，兼容旧文件。

“种群比例调节”总规则默认关闭。打开并保存后，只延缓超额类别的新孕育；不足类别依靠自然繁殖，不再直接生成。关闭总规则不干预繁殖比例，且保留世界中的目标配置。已开始的孕育和手动生成继续。来源与比例在第二页随机生成的维持比例窗口编辑。

<a id="doc-4ecb017bf956-每轮怎样变异"></a>

#### 每轮怎样变异

名额按当轮全部存活实体数×比例向上取整，例：100个选10个，525个选53个；0%不选任何实体。尸体不是活体，不进入分母。每轮无放回随机选取，不按注册顺序或近邻序号固定挑选。工匠等基因锁定角色、孵化中的卵、未启用基因计算的实体不进入候选；候选不足时实际抽取数减少。

每个选中身份调用一次真实变异入口，默认类型权重仍为数值出错90%、复制5%、缺失5%；环境压力只影响选中后偏向哪条已有基因。基础基因保护等规则可能使某次操作失败，因此抽样人数不等于保证所有抽中者都发生有效DNA变化。旧实体的`mutationChance`和旧近邻`mergedMutationFraction`字段仅保留兼容，不再决定自然变异。

每帧默认最多执行16个已选身份，余量留在队列。在定时模式下，出生、成年和老年只登记生命阶段并更新属性，不再额外抽签。世界保存记录累计计时、轮次、计数及剩余身份，读档后继续原名单；等待期间死亡或变为受保护角色者跳过，不补抽其他人。

<a id="doc-4ecb017bf956-生命阶段模式"></a>

#### 生命阶段模式

点“模式”按钮切换，再点“应用并保存”。默认定时模式继续保持10%、3游戏天；阶段模式默认基础概率30%，分别在出生、成年、老年首次进入时抽签一次。阶段模式不运行定时抽样，两种方式互斥。锁定基因的工匠与孵化中的卵仍受保护。

阶段实际概率为 `clamp(基础概率 + 环境变异压力 × stageEnvironmentBoost, 0, 1)`，环境加成系数默认0.25，可外部修改。若希望严格0%或100%测试，应同时将该系数设为0。旧实体的独立 `mutationChance` 字段保留兼容，当前由规则卡统一的 `stageMutationProbability` 控制。

切换模式不会补抽已过去的生命阶段；读档也不会再次出生抽签。阶段模式期间冻结定时模式的累计时间和待执行名单，切回后继续。生命阶段位仍按原实体存档保存。

<a id="doc-4ecb017bf956-定时清理尸体"></a>

#### 定时清理尸体

规则卡右上列表选择“定时清尸”。默认关闭，默认周期30游戏天（内部300模拟秒）；界面支持0.1～8640游戏天。打开并保存后，每到一个周期清理当时的未领取尸体，非按尸体死亡年龄计算。暂停时不推进，游戏倍率会影响对应的现实时间。

已被活着的工匠或建群王后领取、运输的尸体保留；下一个周期可再次检查。所有能量块和补给点均保留。删除前再次核验领取状态，避免快照之后工匠接单时货物被删。

清理按帧分摊，`corpseCleanupPerFrame` 默认64，可在外部配置调整。剩余名单、累计模拟时间、周期数和删除数随世界保存；关闭功能会保留进度，重新打开继续。清理不可撤销，启用前可备份世界。

编辑中的两个分页各自保留草稿，“应用并保存”提交已编辑页；未编辑页在外部发生的修改会保留。只读成员不能修改规则。规则为本机全局设置，影响房主的新旧世界；清理进度和变异名单则各自保存在世界存档中。

<a id="doc-4ecb017bf956-观察基因"></a>

#### 观察基因

观察基因已加入基因库与基因树。可在实体基因编辑、基因条件随机生成中添加，模板方式仍严格沿用模板已有基因，不暗中改写旧个体DNA。

|状态|倾向|默认行为|
|---|---|---|
|视野范围|接收更大范围的信息|以基因视野属性×2计算范围，约0.6模拟秒收取一次新信息；追击采用上次观测坐标|
|注意力|持续跟踪已知目标|以基因视野属性×0.8计算范围，约0.1模拟秒更新新目标列表；已知目标坐标每帧可更新|

视野属性曲线默认20到40：基因值25的“视野范围”约50距离，值75的“注意力”约28距离。定义可在基因工具中调整并随世界保存；倍率/刷新周期配置在`Assets/Resources/Entities/observation.json`。

自主行动只使用视野内投递的信息，并继续检查同群、体型、食性、领地和隐藏寄生资格。出视野、停用或死亡目标不能继续定位。禁用已有观察基因会撤销视野；没有观察基因的旧实体保持原感知范围，避免升级后全体失明。明确点选的手动攻击/RTS攻击指令保留原操作语义。

## 实体顺序计划与优化配置

原文档：`Docs/操作指南/实体顺序计划与优化配置.md`

<a id="doc-c72da1c6b893-实体顺序计划与优化配置"></a>

### 实体顺序计划与优化配置

普通实体会按自身能力排列能量块、尸体取食目标，当前耗尽后继续下一项；这些目标也随世界保存。

工匠现在会规划一组周围可采集目标，完成采集与交付后继续下一项。默认最多12项，未来项不会提前占用。目标被其他工匠取走、死亡/移除或失去采集资格时跳过。

饱食不足时优先去补给，原工作排到后面；吃到恢复线后继续原任务。运输货物仍保留。没有可用补给时会继续采集和交付以建立补给，不会把营养凭空补满。队列和正在搬运的货物随世界保存，读档后继续。

可修改安装目录中的[计算优化配置](../../config/simulation_optimization.json)：

|参数|默认|作用|
|---|---:|---|
|activeExecutionPlan / activeComponentReuse|true / true|活跃执行过滤/批内组件复用；两者都false时直接遍历原逻辑，不再维护计划；约2秒热加载|
|taskQueue|true|启用多项排队；关闭时仍可执行当前采集|
|workerQueueLimit|12|工匠与普通实体每类新建资源计划的目标上限|
|decisionSeconds|0.25|行动意图查询周期，模拟秒|
|mateSearchSeconds|0.5|无有效配偶时重新寻找的间隔，模拟秒|
|directGroundQueries|true|生成星球直接定位真实三角形；关闭后使用物理射线|
|groundNormalAngleDegrees / groundVelocityEpsilon|0.15 / 0.0001|省略相近旋转/速度写入的阈值；精确归零保持不变|
|groundProbeSeconds|0.2|保留给旧GravityProbeCache接口的最长缓存时间；当前默认入口改为直接查询|
|resourceCellSize / maximumResourceCells|32 / 4096|资源格大小；超大范围查询改扫紧凑分类坐标的格数上限|
|groundProbeMoveTolerance / groundProbeVerticalSpeed|0.1 / 0.1|旧接地缓存允许的位移/径向速度，保留兼容|
|expressionCache / expressionCacheLimit|true / 256|纯表达缓存开关/容量|
|localCompetition|true|营养竞争局部失效|
|singletonKernel|true|孤立静止实体使用有效结算核|
|resourceInstancing|true|共享资源材质启用实例化；新建材质时应用|
|visualRefreshSeconds|0.25|能量块外观统一刷新间隔，真实秒|
|lightDistance|80|距镜头超过此距离关闭能量块点光源，物件本身仍可见|

配置约2秒自动检测修改，支持中文注释；格式或数值非法时保留原有效参数。开启/关闭优化不免除营养消耗、寿命、真实繁殖费用或实际资源数量限制。

饥饿开始线与进食速度属于蚁群世界规则；成员恢复线仍在`config/gameplay.json`的`memberFeedResume`。已有世界的蚁群规则保存在各自存档中，修改全局优化节奏不会替换这些生态规则。

## 尸体批次与性能回退

原文档：`Docs/操作指南/尸体批次与性能回退.md`

<a id="doc-a8f6f718d89b-尸体批次与性能回退"></a>

### 尸体批次与性能回退

游戏根目录 `config/simulation_optimization.json` 可用外部编辑器修改，支持中文注释，运行中约每 2 秒检测。发布版同样使用此路径。非法配置会告警并保留上一次有效配置。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| corpseBatchRendering | true | 尸体身体和叉号用空间实例批次显示；关闭后恢复原对象显示，不删除尸体 |
| corpseBatchSize | 256 | 每批实例上限，范围 1～511；太小会增加绘制提交 |
| corpseRenderCellSize | 128 | 尸体显示空间格大小；独立于食物搜索格，较大格减少小批次，但会增加保守提交的对象 |
| resourceInstancing | true | 实例化总开关；关掉也会退出尸体批次。已有能量块材质的开关需重载世界 |
| foodSearchMoveTolerance | 0.1 | 食物短周期缓存允许的相对星球位移，世界距离单位；实际搬运会更新资源坐标 |
| decisionSeconds | 0.25 | 既有行为决策间隔，使用模拟秒；食物查询短缓存沿用真实计时并随实时资格失效 |
| groundProbeSeconds | 0.2 | 接地三角形可复用的物理时间上限；超出三角形/位移/速度限制会提前取样 |
| groundProbeMoveTolerance | 0.1 | 接地复用最大位移，世界距离单位 |
| groundProbeVerticalSpeed | 0.1 | 允许复用时最大径向速度，世界距离/物理秒 |
| directGroundQueries | true | 生成星球直接定位真实三角形；不支持的地形自动回退物理射线 |

“设置 → 日志与诊断 → 采样游戏性能”仍保留结束提示和报告路径。新报告补充食物搜索、接地和尸体批次细项。取样时保持平常镜头、1倍速及相同存档；运行与暂停分别采样可以分开看模拟和渲染开销。比较时同时记录实体、尸体、分辨率和镜头，不能把清空世界后的帧数当作同数量优化。

尸体仍能点选、查看、被工匠运输和被食腐实体吸收。此显示开关不会启用定时清尸，也不会更改繁殖、生命和变异规则。

## 锁帧性能采样与实体编辑

原文档：`Docs/操作指南/锁帧性能采样与实体编辑.md`

<a id="doc-c3c0264fec7d-锁帧性能采样与实体编辑"></a>

### 锁帧、性能采样与实体编辑

- 打开设置 → 声音与画面 → 锁帧（最大帧率），左右按钮切换，不限制/15/20/30/45/60/90/120/144/165/240可选。修改立即应用，点“保存设置”后下次启动恢复。目标应选择机器能稳定达到的值；锁帧不能把不足的帧率提高到目标。
- 设置 → 日志与诊断 → 采样游戏性能，然后返回游戏正常操作约8秒。完成后会在游戏画面上方提示12秒，并显示实际JSON报告路径；设置页也保留结果。启动或保存失败同样直接提示。报告位于日志目录的performance子文件夹。报告同时记录活体、资源、分辨率和帧率上限。需要复现卡顿时保留报告及当时操作说明。
- 在实体详情原摘要标题右侧点击“编辑”，可更改幼年、成年、老年，或生命、饱食度、储存营养。此弹窗不挤占原详情布局；普通联机成员没有修改权限。修改阶段会同步真实寿命边界，保存世界后保留；手动修改不会额外触发阶段变异。退回幼年会释放该实体的运输任务。
- 鼠标悬停在整张基因卡上可查看失效原因、有效值及抑制详情，包括禁用、阈值、环境、角色和其他基因的抑制；编辑弹窗仅保留编辑功能。表达仍生效但缺少状态或复制强度为0时会单独说明。
- 右键尸体沿用同一详情面板，显示已死亡、剩余营养、生前阶段和基因，字段只读；悬停基因卡可查看归档原因，尸体不能执行活体编辑。新产生的尸体保留这些信息。旧尸体原档未保存的基因和年龄不能推算，会明确标为未记录。

脚本更新后，请停止Unity播放，等待编译完成，再重新进入存档以安装新的菜单组件。


性能报告现增加GPU Frame Time和镜头上下文：viewStart/viewEnd/viewWorst中的entityView可识别操控状态，configuredSpeed/deliveredSpeed/pendingGameTime分别是选择倍率、实际交付倍率和积压模拟时间。GPU无数据会标为不可用；最大GPU时间与镜头最慢回调不是严格逐帧关联。请在最卡的操作中采样，特别保留当时是否开多倍速。

随机/自动生成共用AutomaticSpawn计时，手动批量生成时该项也会增加；其中ProducerPlacement是选择生产者投放位置的包含子项，二者不能相加。

## 运行日志与测试

原文档：`Docs/操作指南/运行日志与测试.md`

<a id="doc-9feef312b02a-运行日志与崩溃排查"></a>

### 运行日志与崩溃排查

游戏启动后自动保存文件日志和诊断记录，编辑器播放、Windows 普通发布版均生效，不需要开启开发者模式。

<a id="doc-9feef312b02a-出问题后怎么做"></a>

#### 出问题后怎么做

1. 记下发生时间和最后进行的操作。若游戏卡住，后台诊断线程仍可能持续保存心跳信息。
2. 闪退或被强制结束后，重新启动游戏。系统会标记上次未正常结束的会话。
3. 进入游戏“设置”，点击 **导出诊断包**，等待显示“已保存”及 ZIP 文件路径。
4. 点击 **打开日志文件夹**，在 `diagnostics/exports` 中找到诊断包；提供该文件及复现步骤。联机问题请分别导出房主与成员的诊断包。

无法重新启动时，直接保留整个 `logs` 目录。不要只截取控制台最后一行，它可能不是最早出错的位置。

<a id="doc-9feef312b02a-日志在哪里"></a>

#### 日志在哪里

- 默认：游戏可执行文件旁的 `logs`；编辑器播放时为工程根目录的 `logs`。
- 游戏目录不可写时：自动使用 Unity 当前用户数据目录下的 `logs`。设置中显示的是实际路径。
- `latest-log.txt`：最近创建的常规日志文件完整路径。
- `session-日期-时间-进程号-随机标识-分段号.log`：每次启动独立的完整游戏输出，超过容量后分段。
- `diagnostics/run-唯一标识/`：每次启动独立的崩溃诊断记录。
- `diagnostics/exports/diagnostics-日期-唯一标识.zip`：手动导出的诊断包。

多个游戏实例各自写入不同的文件和会话目录。系统用独占文件锁识别还在运行的实例，不会仅凭旧目录存在就将其判定为崩溃。

<a id="doc-9feef312b02a-诊断包里面有什么"></a>

#### 诊断包里面有什么

| 文件 | 用途 |
| --- | --- |
| `session.txt` | 游戏版本、构建 GUID、Unity 版本、操作系统、CPU、GPU、内存及实际日志/原生崩溃目录 |
| `critical.log`、`critical-previous.log` | 独立于常规队列刷盘的错误、断言、脚本异常及调用栈、线程编号；包括未处理异常和未观察的 Task 异常 |
| `state.json` | 最近一次主线程采样：场景、存档标识、实体数、加载/保存状态、运行/暂停、联机角色、帧耗时、模拟倍率、待补算秒数、Unity 内存及常规日志写入故障 |
| `health.txt` | 后台定期保存的时间、距最后主线程心跳的间隔、疑似停顿状态、真实进程工作集、托管内存、最近错误及限流数量 |
| `events-tail.log` | 最近一段游戏输出，即使常规日志随后轮转也能保留一份现场 |
| `player-tail.log` | 发布版 Unity 原始日志尾部，可补查引擎、渲染和原生层报错 |
| `completed.txt` | 日志系统完成正常关闭的标记；终止性未处理异常不会被后续关闭覆盖为正常 |
| `abnormal-exit.txt` | 下次启动发现上次缺少正常结束标记时生成；强制结束、断电、崩溃或诊断写盘故障都可能导致此标记 |
| `native-candidates/` | 若系统有生成且能够读取，收集同游戏原生崩溃目录近 48 小时的 `.dmp`、`.log`、`error.txt` 候选文件 |
| `README.txt` | 文件说明，以及文件过大、预算不足、无权读取等遗漏原因 |

**异常退出标记不等于已经确定崩溃原因。** 原生转储也可能来自同一游戏的另一个实例，需要结合时间和进程号判断。脚本日志无法保证捕获访问违规、显卡驱动故障、断电或严重内存不足时的最后一条信息；这类问题优先结合 Unity 原始日志和原生转储分析。

编辑器不自动打包 `Editor.log`，避免混入 Unity 授权相关信息；其本机位置仍记录在 `session.txt` 中。诊断包不包含存档或完整实体基因，但日志可能含本机路径、玩家命名和网络地址，分享前可检查。

<a id="doc-9feef312b02a-如何看卡顿或闪退"></a>

#### 如何看卡顿或闪退

- 先看 `critical.log` 中最早的相关错误和调用栈，再结合 `events-tail.log` 查看当时的加载、存档和联机操作。
- `health.txt` 的后台时间持续更新，而 `state.json` 的主线程时间不再更新，且心跳间隔不断变大：提示主线程停顿。暂停游戏仍有主线程心跳，和卡死不同；操作系统挂起应用也可能产生长间隔。
- `pendingSimulationSeconds` 持续增加：模拟跟不上所选倍率。配合实体数、帧耗时和内存判断负载。
- 主线程采样默认每秒一次，磁盘快照每 5 秒一次，快照是最近现场，不是完整录像。
- `fileLogFailure` 或“诊断写盘故障”不为空：优先检查磁盘空间、文件权限和是否有其他工具独占文件。游戏设置也会显示对应故障。

常规日志继续保存世界加载/保存、随机生成任务、联机连接、权限拒绝、断线等操作，不逐帧打印输入或每个实体的基因。

<a id="doc-9feef312b02a-容量与性能"></a>

#### 容量与性能

常规日志由后台线程写入，默认每 0.5 秒刷新；错误立即触发该队列的刷新。独立紧急日志在错误回调返回前写入并请求系统刷盘，因此不依赖普通队列是否已排空。严重的存储故障仍可能使写入失败，并会报告故障。

| 项目 | 默认设置 |
| --- | --- |
| 常规日志 | 每段约 4 MiB，保留最近 20 段 |
| 紧急日志 | 每段约 512 KiB，当前与上一段共两段 |
| 错误风暴 | 每秒最多独立记录 8 条，省略数量可查；终止性未处理异常越过此限流 |
| 主线程状态采样 / 后台快照 | 1 秒 / 5 秒 |
| 疑似主线程停顿阈值 | 15 秒 |
| 普通 / Unity 原始日志现场尾部 | 各最多约 256 KiB |
| 诊断会话 | 最近 8 次；仍在运行的实例不删除 |
| 导出包 | 最近 3 个；收集文件未压缩总量预算 64 MiB，原生候选最多 16 个 |

超过导出预算的转储会被跳过，并在包内说明。旧诊断会话也受保留策略限制，出现问题后应及时导出。清理仅处理本功能产生的会话和导出包，不删除存档或其他文件。

配置位于 `Assets/Resources/runtime_logging.json` 和 `runtime_diagnostics.json`，修改后重新构建生效。两者的 `enabled` 分别控制普通文件日志和崩溃诊断；关闭崩溃诊断不影响普通输出。

<a id="doc-9feef312b02a-开发回归"></a>

#### 开发回归

在隔离工程通过 Unity 执行 `DarwinPark.EditorTools.RuntimeDiagnosticsRegression.RunBatch`，检查真实 Unity 日志回调、线程错误、异常退出标记、主线程停顿、文件锁、错误限流/轮转、写盘失败、内存计数及诊断包内容。

`PlayerBuildLogRegression.RunBatch` 另行执行真实 Windows 非开发版构建和常规日志回归。发布版还需实际启动、强制结束并重启，不能以编辑器编译代替崩溃恢复验证。

## 地形升级与性能排行

原文档：`Docs/操作指南/地形升级与性能排行.md`

<a id="doc-8a53f4c1b199-地形升级与性能排行"></a>

### 地形升级与性能排行

<a id="doc-8a53f4c1b199-旧世界升级"></a>

#### 旧世界升级

旧存档正常进入时保留原地形。底部第一页点击“地形”，在地形参数窗口选择“一键升级高原 / 河流 / 盆地（先备份）”。已有第二版地貌会显示关闭选项。升级在加载界面重建地形，随后保存并返回当前世界。

原世界完整备份位于save/<世界编号>/backups/terrain-<时间>-<标识>.json。需要回退时先退出该世界，另外备份当前world.json，然后用所需terrain备份复制替换该世界world.json，再从存档页进入。不要在世界仍运行/自动保存时替换文件。

新地貌会改变局部岸线和河湖位置。升级会保留实体和资源身份、数量、营养、日期和离地高度；不是保留全部山坡几何。参数随世界保存，version=1不会因普通读档被静默升级。

<a id="doc-8a53f4c1b199-筛选和规则"></a>

#### 筛选和规则

点击实体统计标题旁“筛选”，条件卡显示在统计正上方，再次点击收起。右侧规则卡填补原筛选横向空位；小窗口可通过“规则”入口展开。

<a id="doc-8a53f4c1b199-查明卡顿位置"></a>

#### 查明卡顿位置

设置 → 日志与诊断 → 采样游戏性能；返回游戏，在卡顿镜头下正常操作约8秒。完成通知会列出前三个已计时脚本及报告位置。返回设置，点“查看脚本与算法排行”。重启后可点“载入最近性能报告”。

“脚本”按自身耗时排序；“方法 / 算法”显示脚本路径、方法、算法范围、自己用时和包含子调用用时、调用数量及最大单次；“引擎分项”显示当前平台能提供的渲染、物理、GPU、等待等统计。支持前20项/全部切换。

同一目录同时保存JSON和中文Markdown报告，保留最近5份。旧JSON仍可载入，但没有脚本明细，须重新采样。JSON的scripts/hotspots可用于后续程序分析。

自身耗时扣除了已计时子调用；包含耗时不能相加。每帧平均用于找持续负担，P95和最大值用于找尖峰。未覆盖的代码不能据此说没有开销，也不能仅凭某一计时范围推断总帧率。可提供有效的最新JSON、卡顿镜头和运行倍率进行对照。
